## Shared DOM and module interfaces

Paths abbreviated below: S=`apps/studio/src/studio`, P=`apps/studio/public`, T=`apps/studio/tests`, B=`T/browser`. Each nested JS context exposes `index.mjs`; consumers use that entrypoint. CSS files are linked explicitly from HTML, with no inline handlers or CSP weakening.

Shell owns exactly these stable mounts: `#studio-app`, `#global-header`, `#left-sidebar`, `#layer-panel`, `#feedback-panel`, `#stage-viewport`, `#canvas-wrapper`, `#painting-canvas` (1000×700), `#stage-overlay` (SVG viewBox 0 0 1000 700), `#feedback-composer`, `#director-hud`, `#tool-dock`, `#right-inspector`, and `#studio-notice` (`role=status`, polite). Header/sidebar containers are authored once; each feature owns only its mount descendants. The viewport controller owns canvas-wrapper sizing/transform. Review owns overlay selection/pins; gesture owns a separate SVG group `data-overlay="brush"`. No feature replaces the canvas or another feature's mount.

Compact shell adds wrappers `#compact-layers-drawer` around the existing layer/feedback mounts and `#compact-inspector-drawer` around the existing inspector mount; these are the same controls, not duplicate compact forms. U1 supplies rail triggers with `data-drawer-open="left|right"`, close buttons with `data-drawer-close="left|right"`, `aria-controls` and `aria-expanded`. U6 owns their reveal/close event handling and dispatches `drawer.set {side:'left'|'right',open:boolean}`; U2 stores `drawers:{left:boolean,right:boolean}` in the local model. Left rail is 52px with Layers/Feedback triggers; right rail is 56px with Properties/color triggers; reveal widths are 260/280px per Gemini. Left tab intent selects the tab and opens the drawer; B/tool selection exposes corresponding properties in compact mode. L opens Layers, C begins review and reveals Feedback; no conflicting C-only tab toggle.

Escape/close returns focus to the opener, or canvas if the opener is unavailable. Canvas pointerdown closes open drawers without resetting values and continues through the normal gesture contract. Flyouts are nonmodal, keyboard reachable, scroll internally when needed, and retain focus while editing. HUD pause, tool dock, file actions, and drawer-close controls must remain reachable at 1024px and short windows: wrap/scroll within their existing zones, preserve visible pause, and never rely on clipped overflow. Both drawers can be opened as shown in Gemini's addendum. V3 checks named-layer selection, full parameter editing, return path, and all actions in both light/dark compact states.

All UI contexts export `mount({root,model,dispatch}) -> {update(model),destroy()}`. They create descendants once, reconcile by stable layer/comment ID, and patch values without replacing focused elements. `dispatch(intent)` returns a Promise for accepted mutation completion or local completion, rejects on failure, and is the sole feature-to-command path. Features handle pending/disabled state and retain local edits on rejection. They never call fetch. Local UI state belongs to `S/model/index.mjs`, server snapshots remain in `StudioState`.

`model` is an immutable view value `{snapshot,tool,size,opacity,color,targetLayer,draft,context,tab,filename,connection,pending,notice,review,viewport}`. `context` is `document|tool|layer`; `tab` is `layers|feedback`; `connection` is `connecting|online|offline|uncertain`; `pending` lists operation keys. `review` is `{phase,rect,text,keepPaused,requestId,generation,artRevision}` with phases `closed|pausing|selecting|composing|submitting|stale|uncertain`. `viewport` is `{mode:'fit'|'manual',scale,x,y}`. `createModel(state)` exposes `get()`, `patch(localFields)`, `subscribe(fn)`, `destroy()`; it subscribes to StudioState events and prohibits patching the server snapshot. Only the central session coordinator applies snapshots. Subscriptions return disposers.

`S/requests/index.mjs` exposes the bounded `StudioRequests` contract in H3: `readState`, `mutate({expectedDocGeneration,run})`, `observe`, `invalidate`. `pause({expectedDocGeneration})` is the shared confirmed pause dispatch: it cancels unsent ordinary intents, awaits outstanding request settlement, sends human pause with the captured generation, and resolves only its accepted current paused response. Generation rotation rejects; refreshing never silently rebinds pause to a different document. An uncertain outstanding mutation permits a fresh read and pause for the same confirmed generation, with the uncertain write still reported. No indefinite pause queue behind automatic retries.

`S/application/index.mjs` exports `createApplication({state,api}) -> {model,dispatch,requests,destroy}`. It composes focused local/mutation/action handlers and injected review/document/viewport services through their public entrypoints. No feature imports another feature's private file. Entrypoint constructs application and mounts features, then starts one coalesced 100ms state polling loop (retry 1000ms after failure); stops timers/listeners on teardown. Revisions and instance IDs gate snapshots; generation rotation cancels drafts/selection activation and preserves review text as stale. Equal unchanged envelopes update heartbeat only. Render on accepted artwork/active change plus local draft changes; control-only JSON object identity does not require rebuilding artwork buffers.

### N3 / paint-at5.22: minimal coordinator dispatch and outcomes

This section is the authoritative clarification for N3; root owns implementation/review through its worker. Retain one `StudioRequests` instance, one poll promise, one sent mutation, and a FIFO of unsent local intents. No general-purpose queue framework. Construct with `{api,acceptSnapshot,onHeartbeat}`: `acceptSnapshot(snapshot)` returns whether it became current; `onHeartbeat(heartbeat)` updates session presence only. Coordinator tracks its latest accepted snapshot/identity and an invalidation counter. Transport reachability remains exclusively in StudioApi's sequenced callbacks; coordinator errors never call setOffline or manufacture reconnect.

- **`observe(snapshot) -> boolean`:** apply through `acceptSnapshot` and advance coordinator identity/revision only when accepted. Reject retired instances/lower revisions through that gate. A generation/instance change invalidates unsent old-context intents. Keep the latest accepted snapshot available internally; callers use model subscriptions for display.
- **`mutate({expectedDocGeneration,run}) -> Promise<snapshot>`:** capture instance and generation at enqueue; require a synchronized current snapshot. At dispatch recheck them, then call `run(api)` exactly once. A valid successful ack in that same still-current instance/generation resolves with the ack even if its revision is older than a poll already accepted. In that case skip applying it: successful execution and display acceptance are separate decisions. Do not reject a known successful write merely because `observe` returned false for lower revision. If identity/generation has rotated, reject stale context and preserve the current display; never replay the old intent. Acknowledgements returned to the caller are evidence of the operation, not permission to replace model state directly.
- **`readState() -> Promise<void>`:** coalesce all callers onto one polling cycle; return only after its current required refresh completes. Capture `{instanceId,revision,docGeneration,invalidationCounter}` when issuing each fetch. Only a matching conditional read can receive `unchanged:true`; validate via the client, never pass that envelope to observe. If captured identity/generation and invalidation counter remain current, merge heartbeat via `onHeartbeat`, retaining the newest known lastSeenAt within that generation; never replace artwork or roll revision back. A stale read's unchanged response has no effects. Reset clears heartbeat through the normal new-generation snapshot. A valid full read uses observe; superseded pre-invalidation reads cannot establish synchronization.
- **`invalidate() -> void`:** increment the counter, cancel unsent intents as stale, mark unsynchronized, and require a full read. If a poll is already running, flag one follow-up full read; start it only when the existing fetch settles. Coalesced callers await that follow-up too. Further invalidations during a fetch repeat this rule with at most one fetch in flight. An old rejection cannot skip the required follow-up; if the latest full read itself fails, reject the cycle, remain unsynchronized, and let the normal polling loop retry. Invalidation alone does not abort or retry a sent write.
- **`pause({expectedDocGeneration}) -> Promise<snapshot>`:** capture requested identity/generation, cancel unsent ordinary mutations as stale, and reserve the next mutation slot for pause. Wait for any already-sent mutation to settle. Following an uncertain result, complete a full refresh first; if it confirms the same captured instance/generation, send pause once. If it rotated or refresh failed, reject without silently rebinding. The uncertain earlier write remains reported and is never replayed. Pause resolves only after its ack corresponds to the latest current paused state and control epoch; a newer paused snapshot at that same epoch can coexist with an older ack. A later resume/new intervention makes the pause result stale. This is a stronger acknowledgement predicate than ordinary mutation success. Concurrent priority-pause callers for identical context may share one pause promise.
- **Rejected promises:** provide `error.outcome = 'stale'|'uncertain'|'validation'`, preserve HTTP `status` and original `cause` where available. Stale means an unsent cancelled/superseded intent, identity mismatch, HTTP 409, or superseded pause acknowledgement. Validation means an explicit non-mutating rejection (local payload validation or known HTTP 400/403/404/405/413), with message preserved. Uncertain means a sent mutation lost its usable response (deadline/network/caller abort/protocol failure) or received a server 5xx that can follow in-memory commit, including persistence flush failure. Cancel dependents and require refresh after stale/uncertain; never relabel uncertainty as validation or auto-retry an unkeyed write. Failed reads preserve transport errors and require synchronization; they do not imply a write occurred.
- **UI integration:** dispatch forwards these rejected promises. Application notices retain actionable error/uncertainty independently of online status; a reachable HTTP error may still leave the studio online. Application sets/removes pending keys in `finally`; use `playback.pause` for the HUD's pending-pause label. A failed comment retry retains its frozen request ID/payload under the review service; the coordinator does not invent idempotency.

Required focused cases: an older successful mutation ack after a newer accepted poll resolves without regression; old-instance unchanged heartbeat is ignored; invalidate during coalesced polling produces one subsequent unconditional fetch and zero overlap; pause cancels unsent work and waits the sent write; lost write response followed by same-generation refresh permits pause without replay; generation rotation rejects that pause; validation/409/5xx/network outcomes preserve distinct error categories and do not change reachability themselves. No UI hierarchy or domain protocol expansion is part of N3.

**N3 preflight distinction and exact ownership exception:** root authorizes N3 to edit only the existing preflight validation throws in `S/api.mjs` to tag their existing TypeError with `code:'INVALID_INPUT'`. This covers `requireGeneration`/context validation before fetch; it changes no payload or response contract. N3 classifies that tag as validation. An untagged TypeError after invoking `run(api)` is ambiguous and remains uncertain, because fetch network failures use TypeError too. An intent rejected before run because the coordinator lacks synchronization is stale/refresh-required, with no claim that a write occurred. N3's tests must assert zero run/fetch on that path and distinguish tagged preflight failure from untagged network failure. Root sequences this narrow api.mjs ownership after its current payload work; G1 server guard remains exclusively root-owned. UI workers make no api.mjs edits.

## Safety and gesture contracts

Use H2 response validation/deadline plus H3 request sequencing for the rebuilt client. All requests keep the 10s deadline through body read, reject malformed endpoint responses, preserve HTTP errors, and sequence connectivity effects. A mutation timeout/network/protocol/flush failure is uncertain; do not retry unkeyed writes automatically. On 409 refresh and preserve user work for renewed intent. Safe comments may retry the exact frozen request ID/payload. A refresh cannot prove an unkeyed stroke's execution history.

Integrate H4/H5/H6 atomically: human HTTP commands/control/project/demo require exact top-level `expectedDocGeneration`; check after full request-body read immediately before mutation, return 409 without mutation on missing/stale context. Use H5's object-form API signatures; no contextless fallback. Agent epoch/grant/CLI contracts remain intact. This guard protects replacement documents; local serialization orders local intents. Same-generation cross-tab human control ordering remains a known protocol limit; UI must not claim global tab locking. Trusted in-process session and recovery APIs retain their current behavior.

Pointerdown freezes document generation, target, tool and parameters; requests pause and captures events locally while awaiting acknowledgement. A local preview may show pending input; no command commits before accepted pause. Pointerup before acknowledgement retains the bounded completed gesture until acknowledgement. Pointercancel/lost capture cancels the gesture; generation rotation invalidates it. Block a second paint gesture while its commit is pending. Limit strokes to 2000 points by bounded sampling with final endpoint preserved; never split one gesture into surprise undo steps. Clamp via `canvasPoint` with transformed canvas bounds. Shapes use positive normalized in-bounds dimensions; zero-area shapes do not commit. Draft and accepted pixels must agree, with local draft removed only once accepted artwork contains the successful commit; uncertain writes clear the visual draft after refresh and retain an explicit uncertainty notice, preventing double-rendering.

Layer name/opacity controls retain their local edit while focused/held; apply on change/blur once, using frozen layer/generation. Snapshot layer disappearance cancels the edit. Native keyboard activation works without pointerdown. Brush parameters update immediately but a held stroke retains frozen parameters. Single-key shortcuts ignore editable targets and composition, use B/Shift+P/M/E/R/O/C/H, Space playback, ] step; Cmd/Ctrl+Z, Shift+Z, S for history/save. Space on a focused button/input preserves native behavior; Hand never borrows Space. Canvas Enter does not invent a paint gesture.

Review: PauseHandshake predicate checks token, accepted same-generation snapshot, and paused state. Expire on cancel/reset/replacement. Freeze artRevision at reviewed selection; artwork changes cause stale review with text retained and submission disabled until explicit reselection. Retrying uncertain submission keeps the same requestId/text/rect/continuation/artRevision. New payload creates a new request ID. Map exact comment transitions and retain errors. Opening a stored pin highlights its region in current artwork; it does not restore a historical canvas. Whole-canvas and region review share the same composer/authorization rules.
