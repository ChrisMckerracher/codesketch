# Verification and release evidence

Production protection rule: Port 4317 is sole production, running the newest released code. Protect production availability and actual artwork: an outage is sev0; stop feature work and restore service first. Only a lead-managed authorized release may restart or replace production processes. Replace production runtime data only during an authorized managed release with a verified backup, and never use `.studio/session.json` for tests. All feature development, automated tests, and browser tests must use separate loopback ports (ephemeral preferred) and separate temporary persistence. Never default development or test `npm start`, `paint`, or test commands to port 4317. Keep served production files under release control; use an isolated checkout for future development. Use no persistent staging runtime.

Native Node tests cover the drawing vocabulary, immutable document reduction, validation budgets, atomic batch rejection, ordered replay, queue replacement, pause/comments behavior, history, project v2 import and obsolete format rejection, strict recovery v1, local persistence, lifecycle readiness/shutdown, and HTTP trust boundaries. Use isolated sessions and temporary directories. Tests must clean up servers and timers. Partial playback progress is tested through recovery snapshots; project v2 saves remain a separate editable-project contract.

`npm run verify` runs syntax, source-size, context-boundary, and zero-dependency checks before the native tests. External browser tooling already installed on the workstation is allowed for verification; keep its runtime packages and generated artifacts outside the shipped application.

Use Playwright CLI against the running loopback server for observable user workflows across the five approved Studio reconstruction journeys defined in `docs/specs/studio-reconstruction.feature`:
1. Native vector typography and geometry: verify the fixed 1000×700 design workspace, uniform viewport scaling (`Math.min(availW / 1000, availH / 700)`) with separate `devicePixelRatio` allocation, crosshair canvas cursor, and zero visible HTML DOM text nodes (all visible UI chrome renders strictly as custom vector paths from the `GLYPHS` engine). Pointer interactions clamp drawing marks strictly to the visible artwork region (`x: 0..740` in expanded mode, `x: 0..1000` collapsed).
2. Drawing tools, pigments, and smoothing: verify switching active tools (`INK`, `PENCIL`, `MARK`, `ERASE`), dragging stroke sliders (Size 1–100 px, Opacity 1–100%, Smoothing 0–100%), selecting from 8 preset quick palette chips with visual selection ring, opening the 2D Saturation/Value color picker matrix with 1D Hue slider (`0°..360°`), sampling canvas pixels cleanly with the eyedropper loupe directly from the offscreen canonical canvas without UI chrome contamination, bounded eraser transparency (`destination-out`, `effectiveSize = min(100, 2 * selectedSize)`), and deterministic local manual-stroke smoothing.
3. Layer stack hierarchy, opacity, and overflow: verify appending new layers (`+ NEW`) with reverse-order UI display, active card expansion (50px height, `#F0F9FF` background with `#0284C7` accent bar) and inline horizontal opacity slider (`x: 810..938`), layer visibility toggle (eye icon), layer stack clipping strictly contained within the 200px viewport (`y: 272..472`), and smooth scrolling with the floating thin 4px paint-stroke scrollbar collinearly aligned at `x = 994`.
4. Spatial feedback selection, fenced submission without separate Resume, and real agent ACK/replies: verify canvas spatial selection marquee (translucent blue wash `rgba(2, 132, 199, 0.14)` with alternating two-tone dashed border and 4 corner handles), anchored composer card with critique input, fenced feedback dispatch capturing `generation`, `artRevision`, and `controlEpoch`. Feedback `SEND` directly authorizes continuation without a separate Resume step. Verify real agent acknowledgement badge (`ACK`), active comment filtering (`status !== 'resolved'`), bounded replies via native CLI (`paint comments reply`) and UI thread view, and layout stability (`CLS = 0.0000`) guaranteed by fixed 216px card width (`x: 752..968`) and collinear thin 4px scrollbar at `x = 994`.
5. Real SAVE, workspace collapse, and keyboard interaction: verify `project.save` triggering document serialization and browser JSON download of authentic v2 schema with a 2.5-second visual confirmation state; sidebar collapse `[ >| ]` expanding canvas workspace from 740 to 1000 design units and `[ EXPAND ]` restoration; and persistent invisible semantic DOM backing elements (`<button>`, `<input type="range">`, `<textarea>`) positioned at descriptor bounds to support native keyboard navigation (`Tab`, `Enter`, `Space`), native IME composition, and system clipboard paste/selection.

Inspect the browser console and test narrow and wide viewports. Verify canvas pixels, offscreen canonical composite sampling, and descriptor bounds with invisible semantic DOM inputs rather than HTML text nodes.

The lead reviews findings and runs verification. Herdr workers implement all code and regression tests. Turn each discovered defect into a bounded worker assignment with reproduction, expected result, and exact file ownership. Repeat checks when fixes change the relevant behavior. Report remaining limitations candidly and keep the final repository state reviewable.

CLI checks use subprocesses against isolated ephemeral studios. Cover offline instructions, strict argument rejection before mutation, bare `paint` and `paint studio start|status|stop|restart`, startup-only flag rejection, runtime reuse, drawing, JSON/stdin, pause/comments, deadlines, and concise output. Native capture tests cover input budgets, local trust, failed browser startup, cancellation, and owned-resource cleanup. `PAINT_BROWSER_TESTS=1 make test-go` includes real-browser pixel checks using the installed browser directly; add `PAINT_STUDIO_TESTS=1` for native CLI integration against an isolated studio. JavaScript tests run on Node; the Go policy cases also invoke the installed Go toolchain. Test automation preserves live artwork and other browser sessions.

Go verification covers formatting, `go vet`, race-enabled native tests, dependency inventory and the 300-line source ceiling with module networking disabled. Native CLI integration uses an isolated studio; browser capture uses synthetic snapshots and the installed browser. Verify a copied binary outside the checkout, offline instructions, shell completion syntax, strict parsing, JSON output and exit status, wait/watch cancellation, bounded streams and atomic writes. Real-browser cases cover committed/active pixels, layer opacity/visibility, erasing, crops, scales, failure/timeout/interrupt cleanup and preservation of existing output. Record platform build results and distinguish cross-compilation from runtime verification.

Capture accepts only current session envelopes containing document, instanceId, revision, and `playback.active`. Reject raw documents, top-level-only active inputs, and missing identity; valid current envelopes ignore unused extra JSON fields and never source pixels from top-level active. Preserve export committed semantics (`committed: true` marks only). Cross-language capture contracts use shared fixtures under `tests/fixtures`: Node checks their snapshots against the real Session implementation and Go consumes the same wire data. Cover every command kind at the playback boundary, including non-drawing operations. Browser interaction checks include native keyboard activation and pointer holds across incoming snapshots; assert the resulting document values as well as the controls.
